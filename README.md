# Тестовое Neowise. AI-помощник для входящих заявок

Ориентир — 45–60 минут. Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту.

## Запуск

В репозитории есть сервер, HTML-страница и имитатор модели. Нужен Node.js 20 или новее. Зависимостей и ключей нет.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт можно задать через переменную `PORT`.

## Что изменить

1. Доработайте `POST /api/triage`. Принимайте JSON с полем `text`, содержащим непустую строку. При пустом, отсутствующем, нестроковом вводе или битом JSON верните HTTP 400 и `{"status":"invalid_input"}`.
2. При корректном ответе модели верните HTTP 200 и `{"status":"ready","topic":"…","draft":"…"}`. Допустимые темы — `delivery`, `pricing`, `other`. Черновик должен быть непустой строкой. При таймауте, ошибке модели или неподходящем ответе верните HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. Ограничьте ожидание модели 300 мс. Оставьте поведение выданного имитатора прежним.
3. Покажите на странице тему и черновик при успехе. Для `manual_review` покажите понятное сообщение менеджеру и очистите предыдущий черновик. Добавьте хотя бы один исполнимый тест для поведения при сбое и инструкцию его запуска.

Для локальной проверки имитатор принимает любой обычный текст. Метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` включают отдельные сценарии сбоя.

- Короткую инструкцию запуска и прогона теста. В описании PR ответьте, где проверяется результат AI, что происходит при сбое, какой AI вы использовали и что проверили самостоятельно. Если работали без AI, укажите это.

После сдачи бот может задать один-два коротких вопроса по вашему коду. Используйте учебные данные. Если не уложились по времени, отметьте незавершённые части в PR.

## Реализация и проверки

Запуск не изменился: Node.js 20+; зависимости, API-ключи и сборка не нужны.

```sh
node server.mjs
```

Автоматические HTTP-тесты на встроенном `node:test` (сервер на свободном локальном порту запускается и останавливается самим тестом):

```sh
node --test
```

Покрыты пустой/нестроковый ввод и битый JSON, все допустимые темы, все пять сценариев сбоя имитатора и восстановление после ошибки. Также тестируется фактическая логика UI в Node.js с минимальным DOM и управляемым fetch: очистка черновика, пустой ввод, ручной разбор и обратный порядок ответов. Эти тесты не заменяют ручную проверку в браузере. Имитатор не изменён.

### Ручная проверка интерфейса

1. Введите «Где доставка?» и отправьте: видны тема и черновик.
2. По очереди отправьте `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]`: виден статус ручного разбора, тема и старый черновик очищены; исходный текст остаётся.
3. Отправьте строку из пробелов: сообщение «Введите текст заявки», старого результата нет.
4. Отправьте `[timeout]`, сразу замените текст на «Какая цена?» и отправьте: актуальный результат — «Стоимость», поздняя ошибка не должна его заменить.
5. При остановленном сервере отправьте непустой текст: интерфейс предлагает ручной разбор. Запустите сервер снова и повторите запрос.

### Технические решения

- API проверяет ввод до обращения к модели, а результат AI — после парсинга JSON: только три разрешённые темы и непустой после `trim()` черновик. Возвращает только поля контракта.
- Дедлайн модели 300 мс через `Promise.race` и `AbortController`; таймер очищается. Сбой модели — HTTP 200 с `manual_review`, `topic: null`, `draft: null`. Некорректный ввод — HTTP 400 с `invalid_input`.
- Интерфейс очищает старый результат при редактировании, новом запросе и сбое, сохраняет исходную заявку и отображает понятный статус. Идентификатор актуального запроса защищает от поздних ответов и ошибок; старый запрос отменяется. Отдельный сетевой таймаут — 3 секунды. Отправка клиенту остаётся решением менеджера.

**Польза для менеджера:** меньше времени на подготовку ответа без риска использовать старый или невалидный черновик; измеряется сравнением времени ручной и AI-assisted обработки одинаковых заявок с учётом исправлений.
